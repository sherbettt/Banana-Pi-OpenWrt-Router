# Как я победить «HEX-магию» в OpenWrt 25.12: восстановление менеджера пакетов `apk`

## Введение

Свежая прошивка OpenWrt 25.12 на роутере OpenWrt One преподнесла «сюрприз» — система из коробки не могла устанавливать пакеты. 
Казалось бы, стандартная процедура `apk update && apk add <package>` превратилась в квест с «магическими» ошибками.


## Диагноз: что сломалось?

При попытке обновления репозиториев `apk update` вылетала ошибка:

```bash
ERROR: wget: exited with error 1
WARNING: updating https://... : unexpected end of file
```

Ключевая фраза из логов, которая указала на первопричину:

```bash
root@OpenWrt:~# wget https://downloads.openwrt.org/...
https://... : HTTPS support not compiled in.
```

**Диагноз:** Встроенный в BusyBox `wget` был собран **без поддержки HTTPS**. 
При этом репозитории OpenWrt 25.12 требуют именно HTTPS. Менеджер пакетов `apk` не мог загрузить ни одного файла, так как внутри он вызывает системный `wget`.

Вторая проблема — `apk` при установке пакета `uclient-fetch` (родной HTTPS-загрузчик OpenWrt) требовал другие пакеты-зависимости, которые тоже нужно было скачать через битый `wget`. Возник **циклический тупик**.

## Анатомия решения: пошаговый разбор команд

### Шаг 1. Создание временного загрузчика

Первый трюк — создать простой скрипт-обёртку, который будет принудительно вызывать `busybox wget` (он есть, хоть и без HTTPS) и заставим его работать через HTTP.

```bash
cat > /tmp/my-wget << 'EOF'
#!/bin/sh
exec /bin/busybox wget -Y off "$@"
EOF
chmod +x /tmp/my-wget
ln -sf /tmp/my-wget /usr/bin/wget
```

**Что происходит:**  
- `cat > файл << 'EOF'` — создаём файл `/tmp/my-wget` с содержимым до `EOF`.  
- `exec /bin/busybox wget -Y off "$@"` — скрипт будет выполнять busybox-wget, отключая проверку прокси (`-Y off`).  
- `chmod +x` — делаем скрипт исполняемым.  
- `ln -sf` — заменяем системную команду `wget` нашей временной заглушкой (флаг `-f` принудительно перезаписывает ссылку).

### Шаг 2. Временный перевод репозиториев на HTTP

```bash
sed -i 's/https/http/g' /etc/apk/repositories.d/distfeeds.list
```

**Что происходит:**  
- `sed -i` — изменяет файл «на месте».  
- `s/https/http/g` — заменяет все `https` на `http` во всех строках.  
- Репозитории теперь указывают на незащищённые HTTP-зеркала, которые `busybox wget` (без HTTPS) может читать.

Теперь `apk update` мог скачать индексы пакетов, но сами пакеты по‑прежнему не устанавливались — `apk add` падал.

### Шаг 3. Установка критических пакетов «вручную»

Хитрость в том, что некоторые базовые пакеты (`gzip`, `tar`, `libnghttp2`, `libcurl4`) уже были частично в кеше или могли быть загружены через временный скрипт. Выполняем:

```bash
apk add curl
```

**Почему именно `curl`?**  
`curl` умеет работать с HTTPS «из коробки» даже в минимальной сборке. После его установки система получает полноценный HTTPS-клиент.

На экране появилось:

```bash
(1/9) Installing libnghttp2-14 (1.66.0-r1)
  Executing libnghttp2-14-1.66.0-r1.post-install
...
OK: 39.8 MiB in 205 packages
```

**Важно:** `apk` при этом всё ещё использовал временный `wget`, но пакеты уже были в локальном кеше (после неудачных попыток они частично скачались). Система дособрала зависимости.

### Шаг 4. Установка родного загрузчика OpenWrt

```bash
apk add uclient-fetch
```

Теперь, когда `curl` и другие базовые утилиты установлены, `apk` может скачать и установить `uclient-fetch` — нативный HTTPS-загрузчик, который и должен быть `wget` в правильной системе.

### Шаг 5. Возврат «боевого» wget

```bash
ln -sf /bin/uclient-fetch /usr/bin/wget
```

Теперь команда `wget` указывает на правильный исполняемый файл, умеющий работать с HTTPS.

### Шаг 6. Возврат репозиториев на HTTPS

```bash
sed -i 's/http/https/g' /etc/apk/repositories.d/distfeeds.list
```

Возвращаем безопасные репозитории — теперь `wget` их понимает.

### Шаг 7. Обновление и финальная проверка

```bash
apk update
apk upgrade
```

Обновление проходит без ошибок. Система полностью готова к установке любых пакетов.

## Стоит ли ставить `wget-ssl`?

Нет, не стоит. У вас теперь есть `uclient-fetch` — это штатный загрузчик OpenWrt, специально разработанный для работы с `apk`. Он легче, чем `wget-ssl`, и полностью решает задачу. Две версии `wget` (с SSL и без) вам не нужны.

Таблица для наглядности:

| Пакет | Размер | Поддержка HTTPS | Статус |
|-------|--------|-----------------|--------|
| wget-nossl | 193 КБ | ❌ | Был в прошивке |
| wget-ssl | 214 КБ | ✅ | Не нужен |
| **uclient-fetch** | **9 КБ** | ✅ | **Установлен** |

## Итог: что мы узнали

1. **OpenWrt 25.12 может выходить с битым `wget`** — это редкий, но возможный баг при сборке образа.
2. **`apk` полностью зависит от внешнего загрузчика** — если `wget` или `uclient-fetch` не работают, система пакетов бесполезна.
3. **Обходной путь существует** — временная подмена репозиториев на HTTP и установка `curl` ломают циклическую зависимость.
4. **После восстановления система работает стабильно** — все последующие обновления проходят гладко.
