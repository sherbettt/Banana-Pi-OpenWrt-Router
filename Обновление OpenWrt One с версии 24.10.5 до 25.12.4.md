## 📚 ПОЛНОЕ РУКОВОДСТВО: Обновление Banana Pi OpenWrt Router EU (OpenWrt One) с версии 24.10.5 до 25.12.4

## 🎯 Цель обновления

Переход со стабильной версии **24.10.5** на актуальную **25.12.4** для получения:
- Исправлений безопасности
- Улучшенной производительности Wi-Fi
- Поддержки новых функций
- Исправления проблем с задержками Wi-Fi 2.4 ГГц

---

## ⚠️ КРИТИЧЕСКИЕ ИЗМЕНЕНИЯ В ВЕРСИИ 25.12.4

### 🔴 **ВАЖНО: Изменены имена сетевых интерфейсов!**

Разработчики OpenWrt переименовали порты для соответствия надписям на корпусе:

| Старое имя (24.10.5) | Новое имя (25.12.4) |
|---------------------|---------------------|
| `eth0` | `wan` (или `sfp-wan`) |
| `eth1` | `lan1` |
| `eth2` | `lan2` |
| `eth3` | `lan3` |
| `eth4` | `lan4` |

**Последствия:**
- Если обновиться **с сохранением настроек** (`sysupgrade` без `-n`) — роутер не поднимет сеть
- **Обязательно** использовать ключ `-n` для сброса конфигурации
- После обновления потребуется **ручная настройка сети**

### 🔍 **Как проверить реальные имена интерфейсов в вашей системе**

После обновления важно убедиться, какие имена интерфейсов использует ваше ядро. Теоретически имена должны измениться, но на практике это зависит от конкретной сборки и конфигурации ядра.

**Команды для проверки:**

```bash
# Показать все сетевые интерфейсы, которые видит ядро
ip link show

# Альтернативный способ - просмотр директории /sys/class/net/
ls /sys/class/net/

# Более детальная информация об интерфейсах
ip addr show

# Узнать, какой интерфейс является физическим WAN портом
ethtool eth0  # или eth1, wan и т.д.
```

**Пример вывода на OpenWrt 25.12.4 (реальная система):**
```bash
root@OpenWrt:~# ip link show
1: lo: <LOOPBACK,UP,LOWER_UP> ...
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> ...  # WAN порт
3: eth1: <BROADCAST,MULTICAST,UP,LOWER_UP> ...  # LAN порт
8: br-lan: <BROADCAST,MULTICAST,UP,LOWER_UP> ... # мост LAN
9: phy0-ap0: ...  # Wi-Fi 2.4 ГГц
10: phy1-ap0: ... # Wi-Fi 5 ГГц
11: pppoe-wan: ... # PPPoE соединение
```

**Важное замечание из реального опыта обновления:**
На практике в OpenWrt 25.12.4 на устройстве OpenWrt One имена интерфейсов **могут остаться прежними** (`eth0`, `eth1` и т.д.), несмотря на заявления в документации. Поэтому **всегда проверяйте реальные имена командой `ip link show`** перед настройкой сети!

Если вы видите `eth0` и `eth1` — значит, ядро не переименовало интерфейсы, и ваши старые настройки `device='eth0'` продолжат работать.

## 🔧 Шаг 0: Органы управления на корпусе OpenWrt One

Перед началом обновления важно понять, какие кнопки и переключатели есть на вашем устройстве и за что они отвечают.

### Расположение элементов

| Элемент | Расположение | Назначение |
|---------|--------------|------------|
| **Переключатель NAND/NOR** | Задняя панель | Выбор загрузочной flash-памяти |
| **Front Button (кнопка на передней панели)** | Передняя панель, слева | Вход в Recovery Mode |
| **Reset Button (кнопка сброса)** | Задняя панель | Сброс настроек / вход в failsafe |
| **Консольный порт USB-C** | Передняя панель, справа | Доступ к serial console |
| **Индикаторные LED** | Передняя панель | Статус загрузки  |

### Режимы загрузки

**Положение переключателя NAND/NOR:**
- **NAND (верхнее положение):** Загрузка из основной NAND flash (стандартный режим работы)
- **NOR (нижнее положение):** Загрузка из NOR flash (аварийный режим для восстановления)

### Кнопки и их функции 

| Кнопка | Как использовать | Что происходит |
|--------|------------------|----------------|
| **Front Button** | Выключите питание → установите переключатель в NAND → зажмите Front Button → подайте питание → отпустите, когда все LED погаснут | Загрузка в **Recovery Mode** (initramfs с LuCI) |
| **Reset Button (задняя панель)** | Нажмите и удерживайте 5-10 секунд во время работы | Сброс настроек до заводских (failsafe) |
| **Reset + питание (NOR режим)** | Переключатель в NOR → зажмите Reset → подайте питание | Полное восстановление NAND из USB |

## 📋 Шаг 1: Подготовка к обновлению

### 1.1 Создание резервной копии текущей системы

```bash
# Создаем полный бэкап настроек
sysupgrade -b /tmp/backup_24.10.5_$(date +%Y%m%d).tar.gz

# Копируем на NVMe (если он у вас есть)
cp /tmp/backup_24.10.5_*.tar.gz /mnt/nvme/backups/

# Сохраняем список установленных пакетов
opkg list-installed > /tmp/packages_installed.txt
cp /tmp/packages_installed.txt /mnt/nvme/backups/
```

### 1.2 Запись текущих настроек (пригодятся после обновления)

```bash
# Сохраняем настройки PPPoE
uci show network.wan | grep -E 'proto|username|password' > /tmp/pppoe_settings.txt

# Сохраняем настройки Wi-Fi
uci show wireless > /tmp/wifi_settings.txt

# Сохраняем правила файрвола
uci show firewall > /tmp/firewall_settings.txt

# Копируем всё на NVMe
cp /tmp/*_settings.txt /mnt/nvme/backups/
```

### 1.3 Проверка целостности NVMe диска

```bash
# Проверяем, что NVMe доступен
df -h /mnt/nvme

# Смотрим, какие данные там хранятся
ls -la /mnt/nvme/
```

## 🔄 Шаг 3: Процесс обновления прошивки

### 3.1 Стандартное обновление (если система загружается)

```bash
# Проверяем, подходит ли прошивка для устройства
sysupgrade -c openwrt-25.12.4-mediatek-filogic-openwrt_one-squashfs-sysupgrade.itb

# Запускаем обновление сбросом настроек (рекомендуется из-за возможной смены имен интерфейсов!)
sysupgrade -n -c openwrt-25.12.4-mediatek-filogic-openwrt_one-squashfs-sysupgrade.itb
```

**Что произойдёт:**
1. Система проверит целостность файла прошивки
2. Начнётся процесс обновления (2-3 минуты)
3. Роутер автоматически перезагрузится
4. После перезагрузки вы попадёте на "чистую" систему 25.12.4

**Примечание:** Если вы хотите сохранить настройки (рискуя возможными проблемами с сетью), используйте `sysupgrade -c` без ключа `-n`. В этом случае после обновления обязательно проверьте имена интерфейсов командой `ip link show`.

## 🚨 Шаг 4: Recovery Mode (если обновление не удалось или система не загружается)

Если роутер не загружается после обновления или вы не можете подключиться к нему, используйте аппаратный Recovery Mode.

### 4.1 Способ 1: Recovery Mode через Front Button (NAND) 

Этот метод загружает **временный initramfs образ** с веб-интерфейсом LuCI. Он не сохраняет изменения после перезагрузки, но позволяет прошить основную прошивку через веб-интерфейс.

**Пошаговая инструкция:**

1. **Отключите питание** роутера (выньте штекер из розетки)

2. **Проверьте переключатель:** Убедитесь, что переключатель на задней панели находится в положении **NAND** (верхнее положение) 

3. **Подключите компьютер** к любому LAN порту роутера (настройте на компьютере автоматическое получение IP)

4. **Зажмите и удерживайте Front Button** (кнопка на передней панели, слева)

5. **Подайте питание** на роутер (вставьте штекер в розетку)

6. **Продолжайте удерживать Front Button** до тех пор, пока **все индикаторные LED на передней панели не погаснут** 

7. **Отпустите кнопку**

8. **Дождитесь, пока загорится зелёный LED** (средний индикатор) — это означает, что роутер загрузил Recovery Mode 

9. **Откройте браузер** и перейдите на `http://192.168.1.1`

10. Вы увидите **временную версию OpenWrt** с LuCI. Теперь вы можете прошить основную прошивку:
    - Перейдите в **System → Backup / Flash Firmware**
    - Выберите файл `openwrt-25.12.4-mediatek-filogic-openwrt_one-squashfs-sysupgrade.itb`
    - Нажмите **Flash Image** и подтвердите действие

После завершения прошивки роутер перезагрузится уже с полноценной версией 25.12.4.

### 4.2 Способ 2: Полное восстановление NAND через USB (NOR режим) 

Этот метод используется, когда NAND flash полностью повреждена и роутер не загружается вообще. Он перезаписывает всю NAND память из NOR с помощью USB флешки.

**Что вам понадобится:**
- USB флешка (FAT32)
- Два файла из директории `mediatek/filogic` :
  - `openwrt_one-snand-preloader.bin`
  - `openwrt_one-factory.ubi`

**Пошаговая инструкция:**

1. **Подготовьте USB флешку:**
   ```bash
   # Отформатируйте USB флешку в FAT32
   # Скопируйте на неё два файла:
   # - openwrt_one-snand-preloader.bin
   # - openwrt_one-factory.ubi
   ```

2. **Отключите питание** роутера

3. **Вставьте USB флешку** в любой USB порт на роутере

4. **Переключите NAND/NOR переключатель** в положение **NOR** (нижнее положение) 

5. **Зажмите и удерживайте Front Button** (передняя панель)

6. **Подайте питание** на роутер

7. **Удерживайте кнопку** до тех пор, пока все LED не погаснут, затем отпустите

8. **Дождитесь**, пока загорится **зелёный LED** — это может занять несколько минут 

9. Система автоматически перезапишет NAND flash. **Не выключайте питание** во время этого процесса!

10. Когда восстановление завершится, **выключите питание** роутера

11. **Переключите переключатель обратно в NAND** (верхнее положение)

12. **Включите питание** — роутер загрузится с восстановленной NAND

### 4.3 Вход в Failsafe Mode (сброс настроек при недоступном веб-интерфейсе) 

Если веб-интерфейс недоступен, но SSH работает нестабильно, можно использовать Failsafe Mode:

1. **Подключитесь к консольному порту USB-C** или используйте SSH

2. **Нажмите и удерживайте Reset Button** (задняя панель) во время загрузки

3. Отпустите, когда LED начнут мигать определённым образом

4. Система загрузится в минимальную среду с IP `192.168.1.1`

5. Выполните сброс:
   ```bash
   mount_root
   firstboot
   reboot
   ```

### 4.4 Доступ к U-Boot меню через Serial Console

Для опытных пользователей: через консольный USB-C порт можно получить доступ к загрузчику U-Boot :

1. Подключите компьютер к порту **Console** (USB-C) кабелем
2. Используйте терминальную программу (screen, PuTTY) со скоростью 115200 бод
3. При загрузке нажимайте любую клавишу для входа в меню U-Boot
4. Появится меню с опциями загрузки и восстановления

## ⚙️ Шаг 5: Первоначальная настройка после обновления

### 5.1 Первый вход в систему

После перезагрузки роутера:

1. **Подключитесь по кабелю** в любой LAN порт (теперь они могут называться `lan1`-`lan4` или остаться `eth1` — проверьте!)
2. **IP-адрес роутера:** `192.168.1.1` (если использовали ключ `-n`) или ваш старый IP (если обновлялись без сброса)
3. **Логин:** `root`
4. **Пароль:** *(пусто, просто нажмите Enter)*

```bash
# Через SSH (если подключены с пустым паролем)
ssh root@192.168.1.1
# Пароль не вводим, просто нажимаем Enter
```

### 5.2 Установка пароля администратора (обязательно!)

```bash
# Сразу после входа меняем пароль
passwd
# Введите новый пароль дважды
```

### 5.3 Проверка реальных имён сетевых интерфейсов (КРИТИЧЕСКИ ВАЖНО!)

**Перед настройкой сети обязательно выполните:**

```bash
# Показать все сетевые интерфейсы, которые видит ядро
ip link show

# Или так
ls /sys/class/net/
```

**Пример вывода:**
```bash
root@OpenWrt:~# ip link show
1: lo: ...
2: eth0: ...     # ← это WAN порт
3: eth1: ...     # ← это LAN порт
8: br-lan: ...   # ← мост LAN
```

**В зависимости от вывода:**
- Если видите `eth0` и `eth1` — используйте эти имена в настройках
- Если видите `wan`, `lan1`, `lan2` — используйте новые имена
- **ВСЕГДА используйте реальные имена из вывода `ip link show`!**

### 5.4 Настройка сетевых интерфейсов

Настройте WAN интерфейс, используя имя из предыдущего шага:

```bash
# Для PPPoE (пример)
uci set network.wan.proto='pppoe'
uci set network.wan.username='ВАШ_ЛОГИН'
uci set network.wan.password='ВАШ_ПАРОЛЬ'

# ВАЖНО: используйте реальное имя интерфейса из ip link show!
# Если интерфейс называется eth0:
uci set network.wan.device='eth0'
# ИЛИ если интерфейс называется wan:
uci set network.wan.device='wan'

uci commit network
uci show | grep network
/etc/init.d/network restart
```

### 5.5 Проверка подключения к интернету

```bash
# Проверяем подключение
ping -c 4 8.8.8.8
ping -c 4 google.com

# Проверяем, что PPPoE интерфейс появился
ifconfig pppoe-wan
uci show | grep network.wan
```

## 💾 Шаг 6: Подключение NVMe диска (если он у вас есть)

**Важное изменение в версии 25.12.4:** Теперь используется пакетный менеджер `apk` вместо `opkg`!

### 6.1 Установка драйвера NVMe и утилит

```bash
# Обновляем списки пакетов (apk вместо opkg)
apk update

# Устанавливаем драйвер NVMe (КРИТИЧЕСКИ ВАЖНО! В 25.12.4 драйвер не входит в базовую прошивку)
apk add kmod-nvme

# Устанавливаем утилиты для работы с дисками
apk add fdisk gdisk e2fsprogs block-mount

# Загружаем драйвер (если не загрузился автоматически)
modprobe nvme

# Проверяем, что диск появился
lsblk
# Должны увидеть: nvme0n1 и nvme0n1p1
```

### 6.2 Монтирование NVMe диска

```bash
# Создаём точку монтирования
mkdir -p /mnt/nvme

# Монтируем диск
mount /dev/nvme0n1p1 /mnt/nvme

# Проверяем, что всё на месте
ls -la /mnt/nvme/
df -h /mnt/nvme
```

### 6.3 Настройка автоматического монтирования

```bash
# Настраиваем автомонтирование через UCI
uci set fstab.@mount[0]=mount
uci set fstab.@mount[0].device='/dev/nvme0n1p1'
uci set fstab.@mount[0].target='/mnt/nvme'
uci set fstab.@mount[0].fstype='ext4'
uci set fstab.@mount[0].options='rw,noatime'
uci set fstab.@mount[0].enabled='1'
uci set fstab.@mount[0].enabled_fsck='0'
uci commit fstab

# Включаем и запускаем сервис
/etc/init.d/fstab enable
/etc/init.d/fstab restart

# Проверяем
mount | grep nvme
```

### 6.4 Сравнение команд: opkg vs apk

| Действие | OpenWrt 24.10.5 | OpenWrt 25.12.4+ |
|----------|-----------------|------------------|
| Обновить списки | `opkg update` | `apk update` |
| Установить пакет | `opkg install <pkg>` | `apk add <pkg>` |
| Удалить пакет | `opkg remove <pkg>` | `apk del <pkg>` |
| Список пакетов | `opkg list-installed` | `apk info` |
| Поиск пакета | `opkg search <pkg>` | `apk search <pkg>` |

## 📡 Шаг 7: Настройка Wi-Fi

В версии 25.12.4 Wi-Fi по умолчанию отключён.

```bash
# Включаем радио
uci set wireless.radio0.disabled='0'
uci set wireless.radio1.disabled='0'
uci set wireless.radio0.country='RU'
uci set wireless.radio1.country='RU'

# Создаём сети (используйте свои SSID и пароль)
uci add wireless wifi-iface
uci set wireless.@wifi-iface[-1].device='radio0'
uci set wireless.@wifi-iface[-1].ssid='OpenWrt_2.4G'
uci set wireless.@wifi-iface[-1].encryption='sae-mixed'
uci set wireless.@wifi-iface[-1].key='ВАШ_ПАРОЛЬ'

uci add wireless wifi-iface
uci set wireless.@wifi-iface[-1].device='radio1'
uci set wireless.@wifi-iface[-1].ssid='OpenWrt_5G'
uci set wireless.@wifi-iface[-1].encryption='sae-mixed'
uci set wireless.@wifi-iface[-1].key='ВАШ_ПАРОЛЬ'

uci commit wireless
wifi reload
```

```bash
uci add firewall rule
uci set firewall.@rule[-1].name='Allow-WAN-SSH'
uci set firewall.@rule[-1].src='wan'
```

## 🎨 Шаг 9 (Опционально): Настройка цветного приглашения командной строки (PS1)

В OpenWrt 25.12.4 используется BusyBox Ash. Вот как сделать приглашение цветным и информативным:

```bash
# Редактируем .profile
mcedit ~/.profile

# Добавляем цветное приглашение
export PS1='\033[1;32m\u\033[1;33m@\033[1;35m\h\033[1;31m($?)\033[0;36m:\033[1;34m\w\033[1;31m\$ \033[0m'

# Добавляем полезные алиасы
alias cls='clear'
alias ls='ls --color=always'
alias ll='ls -alF --color=always'
alias la='ls -A --color=always'

# Применяем изменения
. ~/.profile
```

**Расшифровка цветов и символов:**
- `\033[1;32m` — ярко-зелёный (имя пользователя)
- `\033[1;33m` — ярко-жёлтый (@)
- `\033[1;35m` — ярко-фиолетовый (имя хоста)
- `\033[1;31m` — ярко-красный (код ошибки и приглашение)
- `\033[0;36m` — голубой (:)
- `\033[1;34m` — ярко-синий (путь)
- `\u` — имя пользователя
- `\h` — имя хоста
- `\w` — текущая директория
- `\$?` — код возврата последней команды
- `\$` — # для root, $ для обычного пользователя

**Важно:** В BusyBox Ash вместо `source .profile` нужно использовать `. .profile`

## ❓ Часто задаваемые вопросы

**Вопрос:** Как понять, что роутер находится в Recovery Mode?
**Ответ:** Средний LED индикатор горит зелёным, и вы можете зайти на `192.168.1.1` .

**Вопрос:** Сколько времени нужно удерживать Front Button?
**Ответ:** Держите, пока **все три LED не погаснут** (обычно 5-10 секунд), затем отпустите .

**Вопрос:** После Recovery Mode настройки сохранились?
**Ответ:** Нет, Recovery Mode загружает временную систему. Все изменения пропадут после перезагрузки .

**Вопрос:** Можно ли использовать Recovery Mode с установленным NVMe?
**Ответ:** Да, NVMe не мешает. Recovery Mode загружается из NAND/NOR и не трогает NVMe диск.

**Вопрос:** Почему после обновления нет интернета?
**Ответ:** Возможные причины:
1. Вы использовали ключ `-n` (сброс настроек) — нужно заново настроить WAN
2. Имена интерфейсов изменились — проверьте `ip link show` и используйте правильное имя
3. Не установлен драйвер NVMe (если используете PPPoE с файлами на NVMe)

**Вопрос:** Где `opkg`? Я привык к нему!
**Ответ:** В OpenWrt 25.12.4 пакетный менеджер заменён на `apk`. Используйте шпаргалку:
- `opkg update` → `apk update`
- `opkg install` → `apk add`
- `opkg remove` → `apk del`

**Вопрос:** Как проверить, какие имена интерфейсов на самом деле?
**Ответ:** Выполните `ip link show` или `ls /sys/class/net/`. Используйте ТОЛЬКО те имена, которые показывает эта команда!

**Вопрос:** Нужно ли менять `eth0` на `wan` в настройках?
**Ответ:** Только если `ip link show` показывает интерфейс `wan`. Если показывает `eth0` — оставляйте `eth0`!

## 🔑 Ключевые выводы из реального опыта обновления

1. **Имена интерфейсов могут не измениться** — всегда проверяйте `ip link show`!
2. **Драйвер NVMe нужно устанавливать отдельно** — `apk add kmod-nvme`
3. **Вместо opkg используйте apk** — новые команды, та же логика
4. **Обновление без сброса (-n) возможно** — но после него нужно проверить имена интерфейсов
5. **Все данные на NVMe сохраняются** — диск не трогается при обновлении
